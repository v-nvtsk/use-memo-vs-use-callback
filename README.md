# Тестирование Debounce в React: useMemo vs useCallback

Этот репозиторий создан для демонстрации и сравнения работы хуков `useMemo` и `useCallback` при интеграции с функцией `debounce` из библиотеки Lodash.

## Описание эксперимента

При работе с `debounce` в React важно сохранять стабильную ссылку на дебаунс-функцию между рендерами компонента. Если ссылка будет пересоздаваться при каждом рендере, таймер задержки будет сбрасываться, и дебаунс перестанет работать корректно.

В [src/App.tsx](file:///home/vladislav/temp/test-use-memo/src/App.tsx) наглядно представлены два поля ввода, работающие через разные хуки, а также счётчики создания инстансов дебаунса:

### 1. Подход с `useMemo`
```typescript
const debouncedMemoFn = useMemo(() => {
  lodashCallsInUseMemo++;
  console.warn(`[useMemo] Вызван lodash.debounce! Создан новый таймер.`);
  return debounce((value: string) => {
    console.log(`[useMemo] СРАБОТАЛ ДЕБАУНС: "${value}"`);
  }, 500);
}, []);
```
* **Как работает:** Анонимная фабричная функция запускается **один раз** при монтировании. Она возвращает единственный экземпляр `debounce`, ссылка на который сохраняется при последующих рендерах.
* **Результат:** Счётчик «Инициализаций lodash.debounce» равен **1** и не увеличивается при вводе символов или ререндерах.

### 2. Подход с `useCallback`
```typescript
const debouncedCallbackFn = useCallback(
  (() => {
    lodashCallsInUseCallback++;
    console.warn(`[useCallback] Вызван lodash.debounce! Создан новый таймер.`);
    return debounce((value: string) => {
      console.log(`[useCallback] СРАБОТАЛ ДЕБАУНС: "${value}"`);
    }, 500);
  })(),
  [],
);
```
* **Как работает:** Переданное в качестве первого аргумента IIFE-выражение `(() => { ... })()` вычисляется **при каждом рендере** (на каждый введенный символ или любое изменение состояния компонента), создавая новый таймер, хотя `useCallback` возвращает ссылку на первый созданный экземпляр.
* **Результат:** Счётчик «Инициализаций lodash.debounce» увеличивается **на каждый введённый символ и при каждом ререндере**, наглядно демонстрируя непроизводительные вызовы функции инициализации при использовании `useCallback` таким образом.

## Счётчик ререндеров и принудительный ререндер
В верхней части страницы добавлен счётчик общего числа ререндеров компонента `App` и кнопка **"Вызвать ререндер"**.

При нажатии на кнопку:
1. Компонент `App` рендерится заново (число ререндеров увеличивается).
2. Счётчик инициализаций дебаунса в блоке `useMemo` **остаётся равным 1**.
3. Счётчик инициализаций в блоке `useCallback` **увеличивается на 1**, доказывая, что создание функции происходит на каждый рендер, даже если ввод текста в это поле не происходил.

## Просмотр исходного кода на странице
В самом низу страницы добавлена кнопка **«Показать исходный код App.tsx»**, которая открывает панель с кодом приложения. 

Код импортируется динамически с помощью функции Vite:
```typescript
import rawAppCode from './App.tsx?raw';
```
Это гарантирует, что отображаемый на странице код всегда актуален и полностью соответствует тому, что выполняется в браузере в данный момент, без какого-либо дублирования исходников.

## Установка и запуск

1. Установите зависимости:
   ```bash
   npm install
   ```

2. Запустите сервер для разработки:
   ```bash
   npm run dev
   ```

3. Откройте приложение в браузере и наблюдайте за поведением счётчиков прямо на карточках или в консоли (F12).
